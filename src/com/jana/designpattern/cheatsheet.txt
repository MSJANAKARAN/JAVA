## 10 Must-Know Design Patterns — Interview Quick Revision 

### 1. Singleton

Type : Creational
Explanation : Ensures only one instance of a class is created throughout the application and provides a global access point to that instance
Example : Centralized Logger / Configuration Manager / Cache Manager shared across services.

### 2. Factory

Type : Creational
Explanation : Provides a way to create objects without exposing the object creation logic to the client. 
				i.e) Encapsulates object creation and returns the appropriate implementation.
Example : `PaymentFactory` creates UPI / Card / NEFT / RTGS payment objects.

### 3. Builder

Type : Creational
Explanation : Used to construct complex objects step by step, especially when an object has many optional fields.
Example : Build a `LoanApplication` with customer, amount, tenure, insurance, collateral, etc.

### 4. Strategy

Type : Behavioral
Explanation : Defines a family of different algorithms, encapsulates each one into a separate class, and allows the algorithm to be selected at runtime.
Example : Different payment strategies for UPI / Card / NEFT / RTGS.

### 5. Adapter

Type : Structural
Explanation : Allowing two incompatible interfaces to work together by introducing an Adapter 
				that converts one interface into another expected by the client..
Example : `VisaAdapter` converts the bank's `pay()` interface to the Visa SDK's `makePayment()`.

### 6. Facade

Type : Structural
Explanation : provides a single, simplified interface to a set of complex subsystems.
Example : `TransferFacade` coordinates authentication → balance check → debit → credit → notification → audit.

### 7. Observer

Type : Behavioral
Explanation : A one-to-many relationship between objects. When one object (called the Subject) changes its state, 
				it automatically notifies all its dependent objects (called Observers).
Example : Transaction completion triggers SMS + Email + Push Notification + Audit.

### 8. Proxy

Type : Structural
Explanation : Controls access to a real object by placing another object (the proxy) in front of it. Instead of client communicating 
				directly with real object, it communicates through a Proxy, which can perform additional tasks such as security, logging, caching etc...
Example : Security proxy authenticates and authorizes a customer before accessing `AccountService`.

### 9. Decorator

Type : Structural
Explanation : Allows you to add new functionality to an object dynamically without modifying its existing code.
Example : Add Cashback + Insurance + Reward Points to a basic Savings Account.

### 10. Chain of Responsibility

Type : Behavioral
Explanation : Passes a request through a sequence of handlers until one handles it or the chain stops.
Example : Loan Officer → Branch Manager → Regional Manager → Head Office approval.
